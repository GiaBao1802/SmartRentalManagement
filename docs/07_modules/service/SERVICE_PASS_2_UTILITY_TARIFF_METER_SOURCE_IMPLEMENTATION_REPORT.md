## 2. Electricity and Water management

- Added Owner-scoped Admin read and publish API routes. The Owner and actor come only from the authenticated session; foreign Properties return the same 404 behavior as missing Properties.
- If no active Property/type tariff exists, the publish command creates one. If exactly one exists, it uses that tariff. Multiple active tariffs fail closed with a business-readable `409` rather than selecting an arbitrary billing authority.
- A new version is assembled and published in one serializable transaction. Electricity tiers are inserted before publication. Existing DB triggers validate published tier continuity and make published versions/tiers immutable.
- Electricity API input validation checks ordered tier numbers, zero start, exact contiguous boundaries, nonnegative whole-VND price, decimal precision, and one open-ended final tier. Water accepts only a flat integer VND/m³ rate. Utility type fixes the unit and calculation mode on the server.
- Duplicate published effective dates are rejected. Later effective-dated changes require a new immutable version. Existing finalized Invoice snapshots are never updated.

## 5. Meter source and finalized history

The first Invoice's opening readings remain the Contract's `initial_electric_kwh` and `initial_water_m3`. Admin enters them through the existing Contract PATCH flow:

- Draft Contract: sparse update, no revision increment.
- Active Contract: requires `If-Match` and `change_reason`, increments revision and appends a Contract audit record.
- Renewal successor: receives its own readings; predecessor readings are not inherited.
- Later Invoice: remains sourced from the nearest earlier finalized Invoice of the same Contract.

`meter_readings` remains append-only evidence and is not exposed as general-purpose editable history. Finalized Invoice reading/price snapshots remain the billing authority for historical periods.
